# Delegation rule

Generated by claudeconf (constitution §4.7 rule 4). Rewritten wholesale on re-run —
change the harness, not this file.

## Rule

Work may be delegated to a less capable agent or model ONLY when one of the arbiters
below decides the RESULT: it runs on the same tree, it checks what the change means
rather than what it looks like, and it fails loudly when the change is wrong.
Schema-valid, exit-0, and "the tests it wrote for itself passed" are not arbitration.

Work whose mistakes could survive every arbiter below must NOT be delegated. Where
nothing would catch a wrong answer, delegating buys speed with correctness that nothing
checks back — and the wrong answer arrives looking exactly like a right one.

Both halves bind. Fanning work out that the arbiters cover is not recklessness, and
doing it by hand instead wastes the harness; fanning out work they do not cover is not
speed, it is an unreviewed guess.

## Arbiters

- `node_modules/.bin/lefthook run gate` — the full local battery; every milestone at its blocking tier
- `.github/workflows/ci.yml` — the authoritative pre-merge signal

## Never delegable

Whatever any arbiter reports, these stay with the most capable available model or a
human: the control-plane surface (CI workflows, hook-runner config, tool configs,
manifests and lockfiles, scanner exclude files, provisioning scripts and their
checksums, CODEOWNERS), the suppression ledger, `.claudeconf/manifest.json`, and this
file. They decide what the arbiters check, so an arbiter's verdict on a change to them
is circular — it reports the rules as they would be after the change, not whether the
change should have been made.

## What this record is not

The checker verifies that the arbiters named above are the ones this harness actually
has. It does not establish that they are sufficient to catch any particular mistake, and
no file can establish that an agent read this one or followed it. This is a declared
rule, in the same sense the harness is `configured` rather than `enforced`.
